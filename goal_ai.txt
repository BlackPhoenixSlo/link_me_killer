================================================================
D1 Hosting: MOVE TO VPS NOW. Hostinger VPS, Docker Compose. Netlify + GitHub + n8n keep running
   as the live v1 until the VPS version is at parity, then DNS for ofl.ink switches over.
   n8n stays as is (it works) and already lives on the same VPS.
D2 Database + auth + file storage on the VPS: POCKETBASE (one container: SQLite DB, auth with
   email verify/reset, file storage, admin UI, REST + realtime). Replaces GitHub-as-DB and
   secrets.json. Ownership enforced with PocketBase collection rules (user = @request.auth.id).
   Never hand-roll auth.
D3 "Site option ability" = ONE per-link (or per-site default) field, not two checkboxes (AGREED):
     mode: "direct" | "escape_ig" | "deeplink"
   - direct      plain navigation, no overlay
   - escape_ig   try to leave the in-app browser, menu instructions as fallback
   - deeplink    open the destination app via its https app link, web fallback
   The 18+ gate stays a separate boolean (isAdult), independent of mode.
   The current always-on Instagram overlay becomes mode-dependent.
D4 Images -> WEBP: SHARP in the Node app container. Accepts any image (jpg/png/heic/gif/webp),
   fixes orientation, resizes (avatar 512px, background 1080px), outputs webp q80. Client sends
   the raw file; no more "upload .webp only" step. ffmpeg only if video is added later.
D5 Traffic tracking: events collection in PocketBase. /r/:linkId redirect logs user, link,
   country (from VPS geo-ip or Cloudflare header), in-app-browser type, timestamp. Dashboard =
   views, clicks, CTR per link per day per country. /c{id} OnlyFans suffix stays (attribution).
   Replace the global localStorage trackId (contaminates attribution across profiles).
D6 Custom URLs: Caddy (or Traefik) in the compose stack does automatic TLS for any domain pointed
   at the VPS. Per-profile custom domain = a DB field + Caddy on-demand TLS. Spare domains to
   rotate when ofl.ink gets flagged.
D7 Proxies: BONUS, after everything else. Undefined scope; if it means "rotate domains" that
   is D6 with no extra code.
D8 Secret links via JS: keep, as obfuscation. Real win = no real URL in any public file,
   non-guessable ids (random 10+ chars), rate-limited reveal, CORS locked to own origin.
D9 Open question (blocks Phase 3 scope): PUBLIC sign-up or PRIVATE tool for creators you manage?
   Private -> invite-only, no abuse handling. Public -> email verification, content rules,
   abuse reporting; one spammer can get the shared domain banned.

4. INSTAGRAM ESCAPE — technical notes (2026)
================================================================
- Detect: /Instagram|FBAN|FBAV|Threads|musical_ly|Bytedance|TikTok/i (current code only checks Instagram).
- iOS: KEEP x-safari-https:// as an option (it is what we have). Add instagram://extbrowser/?url=
  <encoded https url> as a second option, fired from a user TAP (not from an async fetch callback;
  that loses user activation). Both undocumented; Meta can break either. Always keep the
  "tap ... -> Open in external browser" instruction + copy-link fallback.
- Android: intent://host/path#Intent;scheme=https;package=com.android.chrome;
  S.browser_fallback_url=<encoded https>;end  (fallback missing today; Chrome absent = dead link).
- Keep trackId in the URL in escape mode so it survives "open in browser" (fresh storage).
- Real-device test matrix: iOS/Android x Instagram/Facebook/Threads/TikTok/Safari/Chrome, per mode.
- Riskiest assumption overall: hiding URLs prevents Meta flagging ofl.ink. One shared domain =
  one ban hits every creator. D6 spare domains is the real mitigation.
