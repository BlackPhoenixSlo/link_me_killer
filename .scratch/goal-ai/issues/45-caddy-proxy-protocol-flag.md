- **The flag.** One env variable in compose.yaml's `caddy` service, named for what it holds (the addresses Caddy accepts PROXY protocol from, e.g. `PROXY_PROTOCOL_FROM`). Empty means off: Caddy's listeners read no PROXY header and behave exactly as today. Set to one or more CIDRs, Caddy's listeners accept a PROXY protocol header only from those addresses and take the header's source address as the connection's client address, so the `X-Forwarded-For` entry Caddy writes is the Visitor's, and app/src/click-guard.js's last-entry key is correct with no code change. A header from any other address is ignored or refused, never trusted. tests/e2e.env keeps it off. .env.example documents it with the VPS-side value the Operator fills in: the address range Traefik's container connects from (flag the ASSUMPTION about which Docker network that is).
- **Caddyfile.** Whatever mechanism the local Caddy image supports (observe with `caddy adapt`/`caddy validate` on the local `caddy:2-alpine` image, offline): a `servers` global block with `listener_wrappers { proxy_protocol { allow … } tls }`, an env-selected `import`, or equivalent. The Phase 2 Compose contract checks still pass. No `trusted_proxies` is added: that belongs to 42's Cloudflare lines.
- **Proof that two Visitors stay two clients.** A script under tests/ (as 41's offline check will be, outside the Playwright loop) brings up the local stack once with the flag on and `REVEAL_LIMIT_PER_MINUTE=1`, under a Compose project name that is not `oflinkv2-e2e`, never while `./check.sh` runs. From inside the Compose network (`docker compose run --rm app node -e …` or a file under tests/) it opens raw TCP connections to Caddy's listener and sends `PROXY TCP4 <src> <dst> <sport> <dport>\r\n` followed by a plain HTTP request for `/r/{Link Id}` with the page's own Origin, as the guard requires. Two requests from source A: the second is 429. One request from source B right after: not 429. A connection with no PROXY header from a non-allowed address still gets an ordinary answer. The script tears the stack down (`down -v`) and exits 0 on success.
- **Records.** 23's ticket gains the line the Operator sets in the VPS `.env` and the check it enables (two separate clients each reach their own 429). RUN.md assumptions 1 and 2 are resolved or narrowed in the ticket's Notes.
